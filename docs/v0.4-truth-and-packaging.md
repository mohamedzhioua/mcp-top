# v0.4 — Truth-fix for the Tool-Search era + packaging

Status: SHIPPED in v0.4.0 (pending release)

## Why

Claude Code now defers MCP tool schemas by default (Tool Search: only tool
names and server instructions load upfront; schemas load on demand —
https://code.claude.com/docs/en/mcp). Cursor ships Dynamic Context Discovery.
mcp-top v0.3 prints a fixed per-session tax and `prune -> save ~N/session`
(cli.py:342, 419, 440), which **overstates savings on default 2026 setups**.
v0.4 replaces the point estimate with an honest range + loading regime, breaks
the JSON schema accordingly, and only then adds the install path (PyPI).

## Security: project-scope config is inventory-only by default

A project's `.mcp.json` (Claude) or `.cursor/mcp.json` (Cursor) is untrusted
input -- it ships with a cloned repository, not with the user's machine.
Claude Code itself gates project-scope servers behind workspace trust before
ever launching them. mcp-top mirrors that: project-scope servers are listed
but never launched by default. `--query-project` opts in for a trusted repo;
coverage/output explains why the weight is unknown otherwise ("project scope
not queried by default; pass --query-project in trusted repos"). User/home-
scope querying is unchanged.

## Scope — IN

### 1. Loading regime per server: `deferred | upfront | unknown`

Derived **exclusively from locally observable signals**. No client-version
fingerprinting, no provider/model fallback inference (deferred to v0.5).

Claude Code rules (config keys must be verified against the current MCP docs
before implementation — do not trust this spec's key spelling blindly):

- `upfront`: server-level `alwaysLoad: true`, `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS`
  set (which keeps Tool Search off and cannot be overridden by
  `ENABLE_TOOL_SEARCH`), `ENABLE_TOOL_SEARCH=false` in settings env blocks, an
  explicit Tool Search denial in settings, or `ANTHROPIC_BASE_URL` observed
  pointing at a non-first-party host.
- `deferred`: `ENABLE_TOOL_SEARCH=true` in settings env blocks. Per-tool
  always-load markers raise the floor but keep the regime `deferred`.
- `unknown`: nothing set, `auto` / `auto:N`, or the signal lives outside
  observable files (process env, client version behavior). `unknown` is the
  honest default.

Settings are resolved by documented precedence — managed > local
(`.claude/settings.local.json`) > project (`.claude/settings.json`) > user
(`~/.claude/settings.json`); see https://code.claude.com/docs/en/settings.
The highest-precedence layer that explicitly sets a given key wins that key;
an unreadable higher-precedence layer forces `unknown` for every signal,
because a hidden overriding key in that layer cannot be ruled out. This
replaces flat accumulation across files, which previously forced `unknown`
on any two-file disagreement even when one file's scope should have won
outright.

Codex CLI: `unknown` — upstream Codex has a tool-search/deferred-exposure
mechanism (`codex-rs/core/src/mcp_tool_exposure.rs`), but whether it is
active for a given server is not observable from the locally readable
config surface (0.144.x); record that rationale as regime evidence rather
than asserting `upfront`.

Cursor: `unknown` — the client manages Dynamic Context Discovery outside any
locally observable contract.

Every regime carries an `evidence` list (which file/key produced it).

### 2. Range output replaces the point estimate

Per server: `[upfront_floor_tokens, advertised_max_tokens]`.

- `advertised_max` = current estimator sum over all tool definitions (chars/4,
  still `~`-tagged).
- `upfront_floor` = tool names + server instructions (from the `initialize`
  result, when captured) + always-loaded definitions. `advertised_max` is the
  same whole-definition estimator summed over every tool, plus instructions;
  the two totals share components exactly once each so `floor <= max` is
  provable rather than incidental. Claude Code floor names use the
  client-visible `mcp__<server>__<tool>` name, not the raw tool name.
- Regime `upfront` collapses the range (floor = max).
- Reserved Claude Code server names (`workspace`, `claude-in-chrome`,
  `computer-use`, `Claude Preview`, `Claude Browser`) are never queried and
  never recommended for removal -- Claude Code itself skips them at load
  time, so any measured cost or prune recipe for them would be phantom.
- Human table shows the range; **every** `save ~N/session` string is removed.
  Prune wording becomes: `removes up to ~MAX advertised / >=~FLOOR upfront`.
- Coverage/honesty rules unchanged: estimates stay `~`-tagged, unknowns stay
  loud.

### 3. JSON schema hard-break to `mcp-top/v3`

- `def_tokens` is removed (its v2 semantics are now misleading). New fields:
  `advertised_max_tokens`, `upfront_floor_tokens`, `loading_regime`,
  `regime_evidence`.
- No v2 compatibility flag. CHANGELOG gets a v2→v3 migration table.
- Golden-file contract tests for v3 (human table + JSON fixtures).
- Existing rule kept: never serialize raw ServerConfig (env/args = secrets).

### 4. Remediation recipes (scope-aware, disable-first)

- Claude Code clean suggestions get a copy-pasteable `claude mcp remove`
  command; every other recipe (Codex clean suggestions and candidates, every
  Cursor recipe, and all candidates generally) gets structured edit guidance
  only — never a command. Codex never gets a command, even for a clean
  suggestion: a text-manipulation edit of a live TOML file can corrupt
  multiline strings or comments, so mcp-top only names the exact file,
  `[mcp_servers.<name>]` table, and `enabled = false` line to add.
- Prefer disable/filter over deletion: Codex `enabled = false` /
  `disabled_tools`; Claude Code `claude mcp remove <name> --scope <scope>`
  (verify exact CLI syntax against current docs); Cursor: toggle instructions
  pointing at the exact config file.
- Identify the exact source file + scope in every recipe; shell-quote hostile
  server names in the Claude Code command; JSON exposes argv arrays (Claude
  Code only), source path, and scope.
- The tool still **never edits configs**.

### 5. Packaging & distribution (gated on 1–4 green)

- `pyproject.toml` (PEP 621): name `mcp-top`, console script `mcp-top`
  → `mcp_top.cli:main`, `requires-python >=3.11`, zero runtime dependencies,
  version single-sourced from `mcp_top.__version__`.
- Build wheel + sdist; CI job smoke-tests `pipx install` and `uvx mcp-top
  --version` from the built wheel on Linux/macOS/Windows.
- Release workflow: PyPI **Trusted Publishing** triggered by `v*` tags
  (maintainer configures the PyPI-side trusted publisher; workflow prepared
  in-repo, publish stays behind the tag gate).
- `bin/mcp-top` clone-and-run path keeps working.
