# v0.4 — Truth-fix for the Tool-Search era + packaging

Status: APPROVED 2026-07-17 (joint Fable 5 + gpt-5.6-sol decision, maintainer
confirmed). Correctness gates publishing: the packaging items must not ship
before the measurement-truth items in the same release.

## Why

Claude Code now defers MCP tool schemas by default (Tool Search: only tool
names and server instructions load upfront; schemas load on demand —
https://code.claude.com/docs/en/mcp). Cursor ships Dynamic Context Discovery.
mcp-top v0.3 prints a fixed per-session tax and `prune -> save ~N/session`
(cli.py:342, 419, 440), which **overstates savings on default 2026 setups**.
v0.4 replaces the point estimate with an honest range + loading regime, breaks
the JSON schema accordingly, and only then adds the install path (PyPI).

## Scope — IN

### 1. Loading regime per server: `deferred | upfront | unknown`

Derived **exclusively from locally observable signals**. No client-version
fingerprinting, no provider/model fallback inference (deferred to v0.5).

Claude Code rules (config keys must be verified against the current MCP docs
before implementation — do not trust this spec's key spelling blindly):

- `upfront`: server-level `alwaysLoad: true`, or `ENABLE_TOOL_SEARCH=false`
  found in settings env blocks, or an explicit Tool Search denial in settings.
- `deferred`: `ENABLE_TOOL_SEARCH=true` in settings env blocks. Per-tool
  always-load markers raise the floor but keep the regime `deferred`.
- `unknown`: nothing set, `auto` / `auto:N`, conflicting signals, or the
  signal lives outside observable files (process env, client version
  behavior). `unknown` is the honest default.

Codex CLI: `upfront` — no deferral mechanism exists in the documented config
surface (0.144.x); record the rationale as regime evidence, and fall back to
`unknown` if implementation research contradicts this.

Cursor: `unknown` — the client manages Dynamic Context Discovery outside any
locally observable contract.

Every regime carries an `evidence` list (which file/key produced it).

### 2. Range output replaces the point estimate

Per server: `[upfront_floor_tokens, advertised_max_tokens]`.

- `advertised_max` = current estimator sum over all tool definitions (chars/4,
  still `~`-tagged).
- `upfront_floor` = tool names + server instructions (from the `initialize`
  result, when captured) + always-loaded definitions.
- Regime `upfront` collapses the range (floor = max).
- Human table shows the range; **every** `save ~N/session` string is removed.
  Prune wording becomes: `removes up to ~MAX advertised / >=~FLOOR upfront`.
- Coverage/honesty rules unchanged: estimates stay `~`-tagged, unknowns stay
  loud.

### 3. JSON schema hard-break to `mcp-top/v3`

- `def_tokens` is removed (its v2 semantics are now misleading). New fields:
  `advertised_max_tokens`, `upfront_floor_tokens`, `loading_regime`,
  `regime_evidence`.
- No v2 compatibility flag. CHANGELOG gets a v2→v3 migration table.
- Golden-file contract tests for v3 (human table + JSON fixtures).
- Existing rule kept: never serialize raw ServerConfig (env/args = secrets).

### 4. Remediation recipes (scope-aware, disable-first)

- Clean suggestions get copy-pasteable commands; candidates get structured
  edit guidance only — never commands.
- Prefer disable/filter over deletion: Codex `enabled = false` /
  `disabled_tools`; Claude Code `claude mcp remove <name> --scope <scope>`
  (verify exact CLI syntax against current docs); Cursor: toggle instructions
  pointing at the exact config file.
- Identify the exact source file + scope in every recipe; shell-quote hostile
  server names; JSON exposes argv arrays, source path, and scope.
- The tool still **never edits configs**.

### 5. Packaging & distribution (gated on 1–4 green)

- `pyproject.toml` (PEP 621): name `mcp-top`, console script `mcp-top`
  → `mcp_top.cli:main`, `requires-python >=3.11`, zero runtime dependencies,
  version single-sourced from `mcp_top.__version__`.
- Build wheel + sdist; CI job smoke-tests `pipx install` and `uvx mcp-top
  --version` from the built wheel on Linux/macOS/Windows.
- Release workflow: PyPI **Trusted Publishing** triggered by `v*` tags
  (maintainer configures the PyPI-side trusted publisher; workflow prepared
  in-repo, publish stays behind the tag gate).
- `bin/mcp-top` clone-and-run path keeps working.
